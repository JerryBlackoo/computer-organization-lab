# ISA：软件可见机器的约定

ISA（Instruction Set Architecture，指令集体系结构）是软件与硬件之间的接口规范。
它说明机器码怎样解释、能使用哪些资源、执行后产生什么结果。
**指令系统是 ISA 的核心部分；ISA 还包括数据类型、寄存器、存储与控制状态等约定。**

本目录只保留这一份文档。下面先说明 ISA 的范围，再列出本项目已经定义的教学机器约定。
整机实现 RV32I 40 条基础指令和 RV32M 八条整数乘除指令的教学功能模型，并加入 Zicsr、Zifencei 和部分 M/S/U 特权功能。
另保留原 16 位教学核心。流水线与多周期执行遵循同一套 RV32 语义；当前未做架构兼容认证。

## 整机 RV32 的软件可见约定

| 项目 | 现有约定 |
|---|---|
| 指令 | ADD/SUB/ADDI，AND/OR/XOR、SLL/SRL/SRA、SLT/SLTU 及其立即数形式，MUL/MULH/MULHSU/MULHU、DIV/DIVU/REM/REMU，LUI/AUIPC、JAL/JALR、LB/LBU/LH/LHU/LW、SB/SH/SW、六种整数条件分支、FENCE、ECALL/EBREAK；另有 CSRRW/CSRRS/CSRRC、CSRRWI/CSRRSI/CSRRCI、MRET、SRET、SFENCE.VMA、WFI 和 FENCE.I；未实现编码报告非法指令 |
| 寄存器 | x0～x31，各 32 位；x0 恒为零；算术按 2³² 回绕，不产生有符号溢出陷阱 |
| 编址与数据 | 32 位字节地址、小端；字节任意对齐，半字/字要求 2/4 字节对齐；LB/LH 扩展符号位，LBU/LHU 补零；SB/SH 只写低 8/16 位；MMIO 只接受对齐 32 位访问；独立 Core 的数组以机器字初始化 |
| PC | 指令长四字节，顺序 PC+4；条件分支/JAL 目标为当前指令 PC 加有符号字节偏移；JALR 目标为寄存器加立即数后清除最低位；IALIGN=32，无延迟槽。JAL/JALR 写回 PC+4 |
| 控制状态 | M/S/U 三级；M/S 陷入 CSR、medeleg/mideleg 和 16 项 PMP 子集；机器中断 cause=11/3/7，监督态中断 cause=9/1/5；支持 Direct/Vectored 与 MRET/SRET；共享 RAM 多周期核心支持 satp Bare/Sv32 与 Svade；旧 ROM 流水线不支持 Sv32 |
| 同步异常 | SystemC 整机按委托进入 mtvec/stvec.BASE，分别保存故障 PC、原特权级、cause、tval 和使能栈；故障指令不退休。ECALL 的 U/S/M cause 分别为 8/9/11，EBREAK 为 cause=3；独立教学 Core 默认保留 HostException，构造时可选择 MachineTrap |
| 内存保护 | S/U-mode 的所有取指/读写先检查 PMP，未匹配默认拒绝，Cache 命中不能绕过；S/U-mode 的机器 CSR/MRET 非法；MPRV 可让 M-mode 数据访问采用 S/U-mode 权限；Bare 下 S/U 共用 PMP 策略 |
| CSR 与屏障 | CSR 读写抑制遵循 x0/零 uimm 规则；misa 固定为 0x40141100（RV32/I/M/S/U），mhartid=0；CPU 访存按序确认后退休，FENCE 保守串行化，FENCE.I 同步后续本核取指；SFENCE.VMA 保守清空教学 TLB，受 TVM 限制 |
| 等待中断 | M/S-mode WFI 退休一次并等待局部使能的 pending 输入，S-mode 受 TW 限制；唤醒不受全局使能屏蔽，允许陷入时保存下一条指令 PC；U-mode WFI 非法；等待期间外设和时间继续推进 |

整机使用 MMU、数据 Cache、共享总线和 DIMM；设备寄存器采用 MMIO。
旧 SoC 的程序 ROM 与数据存储分开；SystemC 平台的多周期 CPU 从 DIMM 经指令 Cache 和 MMU 取指。
流水级数、转发、停顿、控制器微指令和 Cache 参数属于实现选择，不改变上述指令语义。
RV32M 除零商为全 1、余数为被除数；有符号商向零截断，最小负数除以 −1 得原值、余数为 0。
逐位算法和执行拍的限制见 [RV32M 运算说明](../docs/rv32-muldiv.md)。
具体实现见 [RV32Core](../soc/core/rv32_core.hpp)、[RV32 译码](../soc/core/decoder/decoder.hpp)、
[流水线](../soc/core/pipeline/README.md)与[多周期控制](../docs/control-unit.md)。

## 原 16 位教学核心

下面保留单总线实验的原有约定；其 16 位编码、SF/OF 与 HALT 只用于 `Core`，不套用于 RV32 整机。

## ISA 需要规定什么

参照所提供的《ISA 规定的内容（指令集体系结构）》材料，可按四类组织：

| 类别 | 需要写清的内容 | 16 位教学核心 |
|---|---|---|
| 指令与操作数 | 指令格式、操作码、操作类型、寻址方式；操作数的个数、类型、来源和约束 | 定长 16 位指令；ADD/SUB 使用寄存器操作数；HALT 无显式操作数 |
| 数据表示 | 数据类型、位数、编码，以及多字节数据的端序和对齐规则 | 16 位整数位模式；有符号解释采用补码；字节流端序、数据访存对齐待定义 |
| 寄存器与存储空间 | 架构寄存器的编号、数量、位宽；地址空间大小与编址单位 | R0～R15，各 16 位；PC 为 16 位字节地址 |
| 可见控制状态 | PC 的更新规则、条件码的定义，以及相关指令的行为 | 顺序 PC 加 2；ADD/SUB 更新 SF/OF；HALT 保持寄存器和标志 |

完整的系统还需要定义中断/异常处理、特权状态与外部 I/O 模型。
这些属于 ISA 的范围，但本项目目前没有相应的机器指令级约定。

## 当前指令格式与语义

所有已定义指令的长度均为 16 位，即 2 字节。操作码字段固定为 4 位。
ADD/SUB 使用三个寄存器编号字段，每个字段 4 位：

```text
位     15        12 11         8 7          4 3          0
       |  opcode  |     rd     |    rs1     |    rs2     |
```

| 指令 | 编码 | 操作数与结果 | 条件码 |
|---|---|---|---|
| `ADD rd, rs1, rs2` | `0001 rd rs1 rs2` | `R[rd] ← (R[rs1] + R[rs2]) mod 2¹⁶` | 更新 SF、OF |
| `SUB rd, rs1, rs2` | `0010 rd rs1 rs2` | `R[rd] ← (R[rs1] − R[rs2]) mod 2¹⁶` | 更新 SF、OF |
| `HALT` | `1111 0000 0000 0000`，即 `0xF000` | 停止执行 | 保持 SF、OF |

ADD/SUB 的两个源操作数和目的操作数都位于通用寄存器，采用寄存器寻址。
它们没有立即数，也不直接访问数据存储器。源寄存器与目的寄存器允许重合，
运算使用本条指令写回之前的源值。HALT 没有显式操作数，低 12 位必须全部为零。
其余操作码或不符合上述格式的编码尚未定义，不能当成 NOP。

例如 `0x1312` 表示 `ADD R3, R1, R2`。若 R1 为 `0x7FFF`、R2 为 1，
则结果 R3 为 `0x8000`，SF=1、OF=1。

**定长指令字、定长操作码与定长指令周期是三个不同概念。**
本机器前两项已经确定；每条指令运行多少时钟周期由 Core 的实现决定。

## 数据表示、寄存器和地址空间

| 资源 | 当前约定 |
|---|---|
| 通用寄存器 | R0～R15，共 16 个，每个 16 位；编号占 4 位 |
| R0 | 普通可读写寄存器，没有硬连零的规定 |
| 整数运算 | 保留结果低 16 位；有符号数采用补码，范围 −32768～32767 |
| PC | 16 位字节地址；已定义指令均占 2 字节，顺序执行时 PC 加 2 并按 16 位截断 |
| 地址空间 | 16 位字节地址可表示 2¹⁶ 个字节位置，即 64 KiB；这不等于实际安装的主存容量 |
| 条件码 | 定义 SF、OF；尚未定义 ZF、CF 或读取/使用条件码的条件转移指令 |

SF 为截断结果的最高位。OF 表示将输入解释为 16 位有符号补码时，数学结果超出可表示范围。
溢出仍保留低 16 位结果，不因此触发架构异常。HALT 的取指也按顺序更新 PC，
停机时保留通用寄存器和条件码。

当前程序以宿主的 `uint16_t` 指令字数组传入。位字段编码已经确定，
**但尚未规定这些指令字序列化为字节流时采用大端还是小端**；不能从宿主机器端序
或某个独立存储模块的字节实现推断整个机器的 ISA 端序。

当前取指端口要求翻译后的物理地址为偶数且落在程序数组内；违反时由模拟器报错。
数据加载/存储指令尚未实现，因此数据宽度、数据对齐、非对齐访问语义与端序仍待定义。
PC 加 2 与字节编址是程序执行规则；PC 在取指的哪一拍更新则是实现安排。

## 可见状态与内部部件的分界

判断 ISA 归属时，要看它是否属于**架构承诺的软件行为**，例如机器码解析、
运算结果或异常语义。主频和执行耗时虽然可以被测量，也不因此成为 ISA 的固定承诺。

| 项目 | 本项目中的归属 |
|---|---|
| 指令的编码、长度、操作语义、寄存器号 | ISA |
| R0 是否恒为零、PC 加多少、SF/OF 的含义 | ISA |
| 端序、数据对齐、异常入口、I/O 编址规则 | 应由 ISA 定义；当前部分待补 |
| 单总线、Y/Z 暂存、IR/MAR/MDR、译码器 | Core 内部数据通路与控制实现 |
| 硬布线/微程序控制、控制信号序列 | 微体系结构 |
| IF/ID/EX/MEM/WB 怎样划分、各阶段几拍、时钟脉冲怎样锁存 | 微体系结构 |
| Cache 的容量、相联度、替换策略、流水线级数、加法器进位方式 | 微体系结构 |

宿主调试接口能查看 IR/MAR/MDR/Y/Z，并不表示机器指令能够访问它们。
FR 是当前保存 SF/OF 的实现部件名；ISA 约定的是条件码的含义和受哪些指令影响。
相同的软件执行约定可以由不同的数据通路与控制时序实现。

## 尚未定义的系统行为

目前没有 LOAD/STORE、立即数运算、跳转/条件转移、CALL/RET、栈操作、浮点或向量指令。
特权级切换、架构控制寄存器、中断入口、异常向量、返回现场以及 I/O 编址也尚未定义。
MMU 的宿主配置接口和 C++ 异常不等于已经定义了相应的 ISA 指令或异常处理协议。

初始化时 PC、寄存器与标志清零，宿主可预设寄存器并开启 MMU，这是当前模拟器的装载/
调试方式；尚未定义机器的复位入口、启动流程或操作系统装载协议。
