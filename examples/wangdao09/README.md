# 第 09 题：16 位单总线旁路和 RV32 流水线转发

在仓库根目录运行：

```bash
./tests/run_wangdao09.sh
```

脚本先验证两种模型，再打印逐拍信息。实验使用同一组输入：`R1=5`、`R2=100`、`R3=20`、`M[100]=6`；先自增，再做减法。

## 16 位：执行阶段的 3 拍、2 拍和 4 拍

`wangdao09::Execution` 是为第 09 题新增的**仅执行阶段实验控制器**：接收真实题目机器码，译码后逐拍产生控制信号，调用现有 `SingleBusDatapath::evaluate()`，统一提交寄存器。它不是已有 `Core` 的完整取指程序，也没有修改原 16 位教学 ISA。当前支持 `inc Rd` 和 `sub Rd,Rs1,(Rs2)`，均要求所用寄存器为直接寻址，末操作数为寄存器间接寻址；不支持题目其他指令或模式。`Y` 对应题目操作数暂存 T，`Z` 对应结果暂存 SR；这仅是此实验中的功能对应。

- 关旁路：`R1 → Y`、`Y → ALU → Z`、`Z → R1`，3 拍。
- 开旁路：第 1 拍总线**同时**送 Y 和 ALU.A，ALU 计算结果在边沿写 Z；第 2 拍 Z 经总线写 R1，2 拍。新 Y 没有在第 1 拍被 ALU 读取。
- `sub`：第 1 拍 R2 经总线送 MAR、并通过额外的地址旁路发起读；第 2 拍 R3 经总线送 Y，独立存储器数据接口同时将响应送 MDR；第 3 拍 MDR 经总线送 ALU，Y−MDR 写 Z；第 4 拍 Z 经总线写 R1。

四拍有明确的**理想化访存前提**：内存请求从第 1 拍的总线直接取得地址，数据在第 2 拍时钟沿前可用，且访存响应不占 CPU 内部总线。默认示例取指端口的五拍读延迟不适用此执行实验。地址为 0xffff 时 16 位数据超出字节数组，报错。这个实验的两个计数均不包含取指或译码。

## 32 位：现有 RV32 流水线

实验调用真正的 `RV32Core`，不修改 RV32 ISA 或伪造题目的单条复合减法指令。映射 `R1→x2, R2→x3, R3→x4`，以 `x5` 为临时寄存器：

```asm
addi x2, x2, 1
lhu  x5, 0(x3)
sub  x2, x4, x5
```

输出每拍 EX 指令地址、两个 ALU 输入的转发来源、数据停顿及退休事件；对比流水线 `forwarding` 关／开。此序列包含取指、填充与排空到第三条退休，共 9／8 拍；加载后使用仍有 1 拍停顿。这里的 MEM/WB→EX **指令间转发**与 16 位 `bus→ALU.A` **指令内旁路**是不同线路，不应将 8 拍称为第 09 题的 4 拍。

RV32 运算是 32 位回绕；为完整模拟 16 位运算，应在需要时对结果截取低 16 位。本示例的值没有发生溢出，故数值相同。
